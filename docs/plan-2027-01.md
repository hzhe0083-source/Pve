## 〇、三方审稿意见（16:00）和据此的修订

三个代理分别从审稿定位、实验设计与统计、工程可行性审了这份计划。结论一致：**按原计划会被拒（ICML 拒、RSS 弱拒），但都能在现有算力内修好。**

1. **现有数据只支持一件事**：冻结的 Pick 加上夹爪探索，在叠方块上 2–3.6M 步学会。它还说明不了「局部」「探针」「冻结」各自有没有用。
2. **对照不公平**：直接微调和 kickstart 都没给探索下限；kickstart 的照抄要到 12.5M 才退完，松手只能那之后出现；唯一一个「不冻 + 下限」的作业也在 2.6–3.1M 学会。→ 主对照改成「直接微调 + 评论家预热 + KL 限制 + 调好的全局下限」「kickstart + 调好的退火长度 + 下限」，每种方法同样的调参预算。
3. **「局部」并不局部**：探针在 68% 的状态上亮，局部和全局的差别主要是「搬运时别抖夹爪」。→ 加时间门控（第 t0 步以后才加噪声）、抓取门控（抓着就加）、平均噪声相同的全局组；每种放法各自调剂量；用「覆盖率相同、与冲突区重合 0/33/67/100%」的区域做剂量-位置回归。
4. **自动定位在这几对任务上是循环论证**：人工冲突区就是源任务自己的成功判据。→ 加「源任务成功判据」这一组；用目标侧的信息定义真冲突区；至少一个没有现成成功判据的设置（图像输入）。
5. **统计**：评估间隔 0.51M 太粗 → 每 2 次迭代评估一次（约 0.1M）、256 个回合；「到 X」= 连续两次 ≥ X；不早停到固定步数；每对任务 3 个独立训练的源专家 × 4–6 个 seed；按「任务对 × 专家」分层的合并 log-rank 和对数正态时间比，最小有意义效应 1.15；先写预注册（带分析脚本的哈希），开发用 seed 和确认用 seed 分开（如 1001 起）。
6. **范围**：C4（多任务局部拆参数）的 RL 部分和 C5（VLA）放不进 1 月的论文 → C4 只保留离线闸门和「冲突在演员还是评论家」的诊断；C5 若走 RSS，可作为扩展章程里的图像输入实验。
7. **工程**：代码进 git，每次实验把 SHA 写进 args.json；队列跳过已完成的作业；记录实际施加的噪声和冲突区覆盖率；每次改代码跑一次逐位一致的冒烟测试。

**修订后的近期安排（本周）**：先做第 2、3、5 条里决定性的一批：叠方块上「方法 vs 调好的全局下限 vs 时间门控 vs 不冻 + 下限 vs 调好的直接微调」，每组 16 个 seed，细评估；同时把 PlaceCube、PushRetreat 跑起来；每个源任务再训 2 个专家。

## 一、论点

机器人用 RL 学一个和已有技能相关的新任务（二值奖励、冷启动）时：
1. **复用**：冻结源策略的隐层（「印象」），不照抄动作。
2. **定位冲突**：用源策略自己的表示找出它和新任务冲突的地方。冷启动时用源任务的「我做完了」探针（源以为做完了、新任务却不给奖励的地方）；有了成功之后，用共享参数上的跨任务梯度冲突。
3. **在冲突处局部解决**：冷启动时只在冲突处加大探索；有信号后只把冲突处用到的少数共享参数拆开，其余继续共享。

要证明：比直接微调、全局照抄（kickstart）、全局探索（组里的夹爪噪声下限）、梯度手术和结构类多任务方法更快、更稳，参数几乎不增加。

| C1 | 复用 + 局部解决冲突，在「延伸型」迁移上又快又稳 | ≥ 4 对任务 × 8 个 seed；对照：直接微调、LP-FT（先冻后放）、kickstart、PEX、残差 RL、全局夹爪下限（组里的做法）、novelty × competence 噪声（Yardimci 2026）、从零 + 噪声 | 「到 0.9 的步数」用 Kaplan-Meier + log-rank（90% 才算学会）；至少 3 对任务上显著快于直接微调和 kickstart |
| C2 | 冲突区能自动找到，不用新任务的标签 | 探针区域 vs 人工区域 vs 同等大小的随机区域 vs 冲突区以外；换冲突区不那么一目了然的任务对 | 探针 ≈ 人工 > 随机 > 区域以外；在 ≥ 2 对新任务上成立 |
| C3 | 局部比全局好 | 同样平均噪声 / 同样覆盖率下，局部 vs 全局 | 在 ≥ 3/4 对任务上局部更快（8 seed，log-rank p < 0.05）；不成立则论文改为「复用 + 在冲突处探索」，不主张局部 |
| C4 | 冲突在共享部分，只拆少数参数就够（你的结构性猜想） | 第 1 道闸门（离线）→ 多任务 RL（4–6 个 ManiSkill 任务共享一个网络）：按冲突选的少数单元拆开 vs 随机选同样多 vs 每任务一个头 vs 全拆开 vs PCGrad / CAGrad / 按层拆（RECON 式）/ 按神经元复制（GradPS 式）/ 共享 + 路由专家；同时诊断冲突在演员还是评论家（MTBench 的说法） | 冲突集中（≥ 50% 冲突在 ≤ 5% 单元）；按冲突选显著好于随机选；参数量相同的对比 |
| C5 | （尽量做）视觉 / VLA | 图像输入的 ManiSkill 策略复用预训练视觉编码器；条件允许时在 VLA（如 LIBERO 上的 RL 后训练）上做探针 + 局部探索 | 至少一个图像输入设置上复现 C1 的方向 |

**候选的延伸型任务对**（新任务 = 源任务 + 新的收尾动作；冲突区由源任务的「做完了」定位）：
- Pick → 叠方块（已有）：多一个松手。
- Pick → 放进容器（PlaceSphere 类）：多一个松手，物体和目标不同。
- Push → 推完再后撤（需写约 20 行的环境）：冲突在手臂维度，不在夹爪。
- Pick → 叠到更高处 / 金字塔（StackPyramid 类）：多步。
- 非延伸型的对照（冲突在中途，探针不该亮）：Push +x → Push 45°、Push → Pull。用来说明方法的适用边界，并引出 C4 的梯度定位。

## 五、风险

1. **局部不比全局强**（C3）：组里的全局下限 0.6 在叠方块上已经到 2.6M 步，和局部的 2.0M 只差约 20%，目前只有 1–2 个 seed。若不成立，论点收窄为「复用 + 在冲突处探索」，靠 C2、C4 撑新意。
2. **探针只适用于延伸型任务**：冲突在中途时它不亮，需要 C4 的梯度定位。
3. **新颖性**：近邻有 Yardimci 2026（熟悉但不会的地方加噪声）、PEX、PARTS、Split-RL、RECON、GradPS。论文要正面比，并强调：用源策略自己的表示定位冲突、不需要新任务标签；局部性有对照证明；探索和容量在同一个冲突位置上统一处理。
4. **算力和时间**：W1 末和 W3 末各有一次收窄论点的机会。
