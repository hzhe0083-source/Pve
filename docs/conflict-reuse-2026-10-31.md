3. **四样同时具备。** 深层非线性网络里精确（任意状态逐位不变）+ 一点旧数据都不用 + 所有技能读同一个向量 + 不按技能分列。
   - P&R 只在线性情形；
   - Anthes 的深层版本要用旧数据，而且是近似的；
   - Progressive Nets、side-tuning、前缀和不共用一个向量；
   - Wołczyk、ClonEx-SAC 要存旧数据，而且是近似的。
4. **同一原理的两种实现。** 「只限制旧读出看得见的那部分」，结构版是零空间适配器（精确，最快，加参数），梯度版是 FN-PPO（不加参数，和整网微调一样快，抓起 0.98，登记规则通过）。
5. **场景和规模。** 闭环 PPO、接触操作；a2r 上给实验室的 10 技能网络加第 11 个技能（方案已出，还没跑）。

**一句话定位（修正后）**：一个精确、不用数据的硬约束，反而让机器人学新技能更快。这和已有报告的方向相反（PackNet、P&R 的非线性版本都报告硬约束有损学习），也不能用已知的「后续状态遗忘」或「门控」来解释。

**引用方式**：Wołczyk、ClonEx-SAC 写成「保留旧能力可以帮助微调，但他们靠存数据的软正则，机制是后续状态的覆盖」，我们和他们的方法、机制都不同。Anthes 写成「我们把他们的建议做成了深层网络里精确、不用数据的版本，结果和他们担心的可塑性下降正好相反」。

**先说结论**

我们新的（按目前查到的）：
1. 构造：冻结的非线性主干 + 每个技能一个非线性残差适配器，写入在非线性之后投影到之前所有输出层的联合零空间；新输出层拷贝旧的；没有输入侧投影；所有技能读同一个向量，对任意输入精确，不用数据。它是增长型学习器，不在 P&R 定理 2.12 的范围里。这一条单看是增量。

**3. 精确性归因：冻结管精确，投影管「一个向量」和速度**

| 性质 | 来自 | 证据 |
|---|---|---|
| 旧技能读自己那一级时精确 | 冻结（主干、之前的适配器、旧输出层的拷贝） | 前缀和读自己那一级：差 0，保持率 0.992 |
| 旧技能读最后一级（共享向量）时精确 | 冻结 + 投影 | 浮点 32 位下 \|W N\|max = 5.6e-8；8 个最终检查点上旧动作最大变 1.2–2.1e-6；不投影时变 0.70–0.92 |
| 和优化器无关 | 投影在前向里 | Adam 下照样精确。P&R 投影的是梯度下降的更新，换成 Adam 就要另外处理 |
| 后面的技能读得到前面的写入 | 增长（前缀和也有） | nsa.py:60 |
| 所有读者读同一个向量 | 投影 | 前缀和改读最后一级时，抓起掉到 0.77–0.90 |
| 新技能学得更快 | 投影（训练动力学） | 同一初始网络：0.61M 对 0.92M，8/8 个 seed |

- 推论（函数类）：主干固定时，投影版的策略集合 {W′(h0 + N g)} 是前缀和集合 {W′(h0 + g)} 的子集（取 g ↦ N g）。nsa64 和 npr 的初始网络相同。所以 0.61M 对 0.92M 不是容量差，是优化差。
- 人话：能写的是「冻结保住旧技能；投影让所有技能共用一个向量，并让新技能学得更快」。

  - 现有数据里根本没有「A 无、B 大」这一格。

- 另外，旧主干在 null(W) 里能提供的有效维数只有约 4（N h0 的参与比 4.1）。这可能是只训输出层慢的原因。

干净的设计：适配器、随机抽样（每格都用 A2 = N·A_rand，所以 4 格初始网络完全相同）、代码和 8 个配对 seed 都固定，只改输出掩码 P = a·N + b·Π。a 表示「写不可见方向」，b 表示「写可见方向」。

- 预测：
  - 可加：t01 = t00 + (t11 − t10) = 12 + 3 = 15 个间隔（1.54M），交互为 0。
  - 路由（理论组的读法）：可见通道单独就给出前缀和的速度，t01 ≈ t11 ≈ 9 个间隔（0.92M），交互约 6 个间隔。
  - 两者差 6 个间隔，8 个 seed 够分开。
- **规则 F（写于这些格的任何运行之前）**：同一份代码 md5，8 个 seed 全部跑完才读。「X 比 Y 慢」的定义和 projection_test.py 相同：中位差 ≥ 1 个间隔，且单侧精确符号秩 p ≤ 0.05。
  - F1：逐 seed 算交互 I_s = t11 − t10 − t01 + t00（单位：间隔）。中位 I ≥ 2 且单侧 p ≤ 0.05，判「不可加」；|中位 I| ≤ 1，判「可加」；其余判「不定」。
  - F2：|中位 (t01 − t11)| ≤ 1，判「可见通道单独就是前缀和的速度」（路由）。只写可见比不写还慢，判「可见通道单独也有害」（接近可加）。其余只报告位置。
  - F3：|中位 (nsa64z − nsa64)| ≤ 1，判「有投影时初始化无关」。nsa64z 比 nsa64 慢，判「随机初始化有贡献」。

**5. 现在能诚实写的理论**

记号：主干冻结，h0(x) 是最后一层；旧输出层 W 是 8×256，新输出层从 W 开始。Π = BᵀB 是到 row(W) 的投影，N = I − Π。适配器 g = A2·tanh(A1 z + a1) + a2，z = [x; h2]。这一级的输出是 h̃ = h0 + P g：我们 P = N，前缀和 P = I。δ = ∂L/∂μ。

- **命题 E（精确性；已证明，已测）**。假设：主干、之前所有适配器和旧输出层的拷贝都冻结；输出层是线性的。
  - (a) 只靠冻结：第 j 个技能读第 j 级时，W_j h̃_j(x) 对任意 x 不变。
  - (b) 加上投影：W_j h̃_K(x) = W_j h̃_j(x) 对所有 K > j、任意 x 成立。原因是两者只差 k > j 各级的 N_k g_k 之和，而每个后面级别的 B_k 都包含 W_j 的行（nsa.py:88 把之前保护的行和当前输出层叠在一起），所以 W_j N_k = 0。
  - 推论（函数类）见第 3 部分。
- **命题 1（路由；对梯度已证明，要按臂分别写）**。
  - ∂L/∂A2 = Σ_s P W_tᵀ δ_s u_sᵀ。P = N 时 P W_tᵀ = N ΔW_tᵀ（因为 N Wᵀ = 0）；P = I 时是 Wᵀ + ΔW_tᵀ。
  - (a) 投影版：适配器的全部梯度（包括 A1）都对 ΔW_t N 线性。新输出层第一次更新之前，梯度严格为 0，和初始化无关；之后适配器只通过「新输出层对 null(W) 的读取」受训。它的输出永远在 null(W) 里，和优化器无关。
  - (b) 前缀和，输出层是拷贝：t = 0 时适配器的梯度在 row(W) 里。这等于通过固定的 W 训练一个旧动作上的残差。
  - (c) 这是关于梯度的命题，不是关于实际一步的。Adam 逐元素归一化，不保列空间：np 第一步只有 34.5% ± 1.5% 落在 row(W)（20 次抽样，噪声优势；纯夹爪信号时是 27%），SGD 下是 100%。原因是 W 主要读少数隐单元（列范数最大值/中位数 = 12.8），而 Adam 把每个单元的步长拉平了。
  - 推论 1：01:15 那节说「零初始化就永远拿不到梯度」，不对。新输出层第一步就有 93% 落在 null(W)，所以零初始化的投影适配器从第二步起就有梯度。nsa.py 的 docstring（「直到拷贝的输出层第一次离开受保护的行」）是对的。nsa64z 一直没跑过。
  - 推论 2：11:30 节「机制假说」和 01:40 节都引了「99.6% 的主干梯度落在旧技能的行空间里」。这是命题 1 在 t = 0、新输出层 = 旧输出层时的恒等式：逐样本梯度就是 J_旧ᵀ δ。不到 100% 只是因为批次状态和锚点状态不同。它既不反映 Adam 实际走的步，也不反映后来的训练，不能拿来支持「改写」假说。
  - 训练好的检查点（place_nsa64_s1，旧代码，只有 1 个 seed）：
    - 新输出层变了 ‖W′ − W‖ = 1.28（‖W‖ = 1.46），其中 92% 落在 null(W)。
    - 适配器的可见部分 ‖Π A2‖² = 2.04，和正交初始化的期望 2.0 一样，也就是没长。
    - 在抓起状态上，新输出层重读旧特征，让「没抓着」时的夹爪均值 +2.15；适配器经新输出层给 −2.59，两者大部分抵消（合计 −0.44）。在目标处两者都往上加（+1.19、+1.26）。
    - 人话：训练出来的零空间特征，让松手只发生在目标处。
- **命题 2（恢复力；只能证弱形式）**。假设 J = p(φ)·q(ψ)，φ 是第一阶段的偏移，p 二阶可微。
  - (i) 奖励对 φ 的唯一作用力是 q·∇p。它在第一阶段最优处为 0，又和 q 成正比，所以松手很少成功时它很弱。
  - (ii) 在最优点附近（∇p(0) = 0，∇²p(0) = −H），力是 −qHφ，对 φ 线性，刚度为 qH。所以「没有一阶恢复力」准确的说法是「没有零阶的力」。
  - (iii) 线性化的梯度流（推导草稿）：dφ/dt = −q K11 H φ + p K12 ∇q，K 是第一阶段状态和松手状态之间的切核。投影去掉的是适配器那部分的 K12（因为 W N = 0），新输出层那部分去不掉。
  - 关键假设在夹爪上不成立。训练时夹爪 std 的下限是 1.0，专家自己是 0.27，手臂是 0.10–0.19。专家抓着时夹爪均值刚过截断点：离目标远时中位 −1.06，近时 −1.01。std 为 1 时，每步约 14% 的采样落在张开一侧。所以每个臂都有一个一阶的「搬运时抓更紧」的力，它和松手冲突。
  - 训练好的 nsa64（同一个检查点）正是这样：夹爪均值在抓着、离目标远的状态上变了 −0.30，在目标处变了 +2.45。命题 2 只对手臂维可能成立。
- **命题 3（门控的计数下界；已证明，但很弱）**。若每次成功都要经过 R，学会需要 N\* 局进过 R 的经验，而每局进 R 的概率 ≤ p̄，那么期望局数 ≥ N\*/p̄（Wald）。
  - 放置的成功是「放好且没抓着」（place_cube.py:45-48），推过去也算，所以这个界只管「抓—搬」这条路径。
- **猜想（还不是定理）：慢的倍数 = (p0/p)^κ**。除了命题 3，还要 4 个假设，没有一个是按构造成立的：
  1. 两臂的 N\* 相同。两臂的梯度路径不同（命题 1），所以这条本身就可疑。
  2. 进度对 p 线性，即 κ = 1。用 Adam 加归一化优势时，κ 可能在 ½ 到 1 之间；信号占主导时趋于 0。
  3. p 不随时间变。否则要比的是各臂在自己窗口上的 ⟨p^κ⟩。
  4. 没有阈值效应。t90 要求确定性评估连续 3 次 ≥ 0.9；确定性策略的第一阶段只要掉一点，t90 就会推迟，这和门控无关。
- **放置上门控的前提很弱（新事实；旧代码，本地数据）**。
  - 数据：两个只训输出层的放置运行，latch_c 的 place_global_s1 和 latch_d 的 place_global_s3。冻结主干、全局夹爪下限 1.0、稀疏奖励、同一个专家，主要设置和 protect 相同。
  - 第 1 次迭代的训练成功率就是 0.89 和 0.87，之后一直 ≥ 0.86；到 t90 为止，按局数加权平均 0.94。确定性评估则在 0.7M 之前都不到 0.05。
  - 所以 PPO 在放置上学的不是「找到稀疏奖励」，而是把目标处夹爪的确定性均值推过去。
  - 成功的局都进过 R，而 p_nsa ≤ 1，所以门控对只训输出层最多解释 1/0.94 = 1.07 倍。它实际慢约 2 倍，门控只占对数差距的 8–9%。
  - **规则 0 已算（15:20，haha-a 上 runs/protect_np 的 train.csv，用 why_test.py 的 rule0，规则写在代码 docstring 里，算之前登记）**：npr 在自己窗口里的训练成功率，8 个 seed 是 0.925–0.930。所以门控最多解释 1.078 倍，实测是 1.500 倍，G_max = 0.18 ≤ 0.3。按登记的规则：**现有数据已排除门控是放置上加速的主因**。叠方块只报告：npr 的训练成功率 0.71–0.75，门控最多解释 1.378 倍，实测 2.25 倍，G_max = 0.40。前 12 次迭代每步 KL 的 npr/nsa64 比，两个任务都是 1.11，前缀和每次迭代的策略步长略大。
  - 叠方块是另一种情况：旧代码的只训输出层和整网微调运行，第 1 次迭代的训练成功率都是 0.12。门控在那里更可能起作用。
- **关于速度的三个候选解释（都没验证）**：
  - H1 门控：可见通道的更新扰动搬运，p 下降，第二阶段的经验变少。在放置上，先验证据弱（上一条）。
  - H2 步长 / 扩散：可见通道主要是在第一阶段状态上加了 Adam 随机游走。调学习率能抹平差距。
  - H3 路由 / 选择性：前缀和适配器的训练信号是旧动作上的残差，经过不正交的 W 串到手臂，松手不够只针对目标。调学习率抹不平。
    - WWᵀ 的条件数是 27.7。经可见通道推夹爪，关节 4 跟着动 14–18%，关节 6 动 10–15%；经新输出层只动夹爪。
    - 手臂各行之间的余弦最大 0.86：经可见通道推关节 1，关节 3 跟着动 72–84%。
- **CPU 玩具模型**（真实的 W、主干和状态，ppo.py 的 PPO/Adam 更新，没有 rollout，所以没有门控；每臂 3 个 seed）：
  - 所有臂学会松手一样快：P(在 R 上张开) ≥ 0.9 出现在第 11.3–12.0 次迭代。
  - 投影让第一阶段的漂移少 12–15%（按 σ 归一化），手臂漂移少 14–26%。
  - 开环下投影不加速。1.5 倍要么来自闭环放大，要么来自玩具模型漏掉的东西。

**6. 机制实验：登记的规则、成本、顺序**

- 代码：实验组写的 why.patch，加了逐段日志、`--nsa_proj random`、`--nsa_restore`、`--adapter_lr`，以及 env 参数 `stage1_cost`。
- CPU 上测过的：
  - 已有的臂（nsa64、npr、np、head_lr）和部署代码逐位一致：train.csv 共有列、eval、old_eval 和每个权重，差都是 0。
  - 逐段计数和真值一致；故意弄坏的记录器能被抓出来（7 处不一致）。
  - 补丁能干净地打到一份新拷贝上。
- 没在真实环境和 GPU 上跑过。β = 0.05 和 λ 是推出来的，没标定过。
- 规则 F 要的两个掩码（P = Π 和 P = 0，A2 都先投影一次，和 npr 一样）还没写进补丁。run_why.sh 和 why_test.py 也要加上只写可见、不写、nsa64z 三个臂。这些要在第 1 步之前并进去，否则 md5 不同，why_test.py 会拒绝混读。

**登记的规则**（全文在 why_test.py 的 docstring 里，写于这条队列的任何运行之前）：
- 共同定义：
  - seed 1–8 配对；t90 和 projection_test.py 相同。
  - 「X 比 Y 慢」= 中位差 ≥ 1 个间隔，且单侧精确符号秩 p ≤ 0.05。
  - p(K) = 第 1..K 次迭代里结束的训练局中，进过 R（或以别的方式成功）的比例。
  - 只读同一份代码 md5 的运行，而且 8 个 seed 要全部跑完。
- 规则 0（不用 GPU，读 protect_np 的 train.csv）：
  - G_max = 中位 log(1/ts_npr) ÷ 中位 log(t90_npr / t90_nsa64)，ts_npr 是 npr 在自己窗口上的训练成功率。≤ 0.3：现有数据已排除门控是主因；≥ 0.7：不排除。
  - 同时打印前 12 次迭代每步 KL 的 npr/nsa64 比。target_kl 是关着的，没有东西卡住它；这个比明显大于 1，就偏向步长解释。
- A0（复现）：两臂 t90 和 protect_np 相差 ≤ 1 个间隔的 seed 各 ≥ 6/8，并且 npr 比 nsa64 慢。不满足就停，下面都不读。
- A1（第一阶段能力）：用前 12 次迭代的 p。中位 p_npr/p_nsa64 ≤ 0.9 且 p ≤ 0.05，判 npr 丢了第一阶段能力。
- A2（门控份额）：G = 中位 log(p_nsa64 / p_npr)（各自窗口）÷ 中位 log(t90 比)。G ≥ 0.7 且 A1 成立：门控是主因；G ≤ 0.3：不是；中间：部分。
- A3（次要）：在 nsa64 的 t90 处，把 npr 的评估失败分成「没松手」「搬丢了」「没抓到」。「搬丢 + 没抓到」占失败的中位比例 ≥ 0.6，判第一阶段失败为主；「没松手」≥ 0.6，判松手失败为主。
- B（同秩随机投影 rp）：rp 比 nsa64 慢，判「起作用的是输出层的那几行」；|中位 (rp − npr)| ≤ 1 且两个方向都不显著，判 rp ≈ 前缀和。
- C（恢复力 rf01 / rf1 / rf10，λ = 0.1 / 1 / 10，每个系数的 α = 0.05/3）：改善 u = d(npr − rf)。中位 u ≥ 差距/2、p ≤ 0.0167，且中位 d(rf − nsa64) ≤ 1：这个 λ 补回了速度。每个 λ 都是中位 u < 1 或 p > 0.0167：没用。
- D（第一阶段代价 0.05：nsa64d、nprd）：r = log(t90 比)，shrink = 中位 r_稠密 ÷ 中位 r_稀疏。≤ 0.5 且 p ≤ 0.05：补上了差距（这是门控的预测）；≥ 0.8：没影响。
- E（适配器学习率 1e-4 / 3e-4 / 1e-3，输出层、log-std 和 critic 保持 3e-4）：
  - 每臂取中位 t90 最低的学习率。落在边上，就先在同样的 seed 上补跑外面一档（3e-5 或 3e-3）。
  - E1：d\* = npr 最佳 − nsa64 最佳。中位 ≥ 1 且 p ≤ 0.05：调参后仍成立；中位 ≤ 0：被调参抹平。
  - E2：在 t90 比 ≥ 1.15 的每个学习率上算 G。都 ≥ 0.7：门控随学习率变；都 ≤ 0.3：不是门控。
- F：见第 4 部分。

组合起来怎么读：
- 门控：A1 成立，A2 ≥ 0.7，A3 以第一阶段失败为主，C 补回速度且 p 恢复，D 补上差距。
- 步长：A2 ≤ 0.3，D 没影响，E1 被调参抹平。
- 结构（路由 / 各向异性）：A2 ≤ 0.3，D 没影响，E1 调参后仍成立；F2 判「只写可见 ≈ npr」，B 判「rp ≈ npr」。
- 「随便哪个同秩投影都行」：rp ≈ nsa64。预期不成立，因为随机投影只去掉 3.6% 的可见梯度。
- 预期（不登记）：规则 0 在放置上给出的门控上限会低于 0.4。同样算法对只训输出层给出 0.08–0.09。

## 11-01 03:45 正式查新：偏增量；决定性的对照是「前缀和」（全文 [survey/nsa-novelty-2026-11-01.json](survey/nsa-novelty-2026-11-01.json)）

14 个代理，从四个角度搜索（参数隔离、零空间/正交子空间、输出零空间含神经科学、机器人加技能），对最接近的论文逐篇打开核实，最后综合。

**结论：偏增量。** 没找到完全相同的构造：给冻结的深层策略加逐技能的残差适配器，把写入投影到之前所有线性输出层的联合零空间里，所有输出层读同一个定宽向量，在 PPO 闭环里检验。但抓起→叠方块这一对结果展示的性质，已有工作都做到过：

| 已有工作 | 已经做到的 | 我们多出的 |
|---|---|---|
| [Peng & Risteski，NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/b63a24a1832bd14fa945c71f535c0095-Abstract-Conference.html) | 定宽共享线性表示、每个环境一个冻结的线性输出层；更新投影到之前所有输出层的零空间，旧任务对所有输入精确不变；新方向随机初始化 | 推广到冻结的非线性主干 + 非线性适配器（他们的非线性版本会遗忘）；闭环 PPO |
| [Progressive Nets](https://arxiv.org/abs/1606.04671)，及其机器人版 CoRL 2017 | 冻结旧列、精确保持、后续任务复用全部旧特征；连「拷贝旧输出层 + 新模块随机初始化」这一招都有 | 只有一点：写进同一个定宽向量，而不是各自一列 |
| [Side-Tuning，ECCV 2020](https://arxiv.org/abs/1912.13503) | 冻结底座 + 旁路网络相加，每个任务一个；增量学习里不遗忘 | 只加一个技能时没有本质区别；技能链里多了「后面的技能读前面写进去的特征」 |
| [Anthes 等，CoLLAs 2024](https://proceedings.mlr.press/v274/anthes25a.html) | 把读出层之前的空间分成读出的值域和零空间，证明只有值域里的变化造成遗忘 | 深层非线性网络里的精确版本。他们的深层变体就是 FN-PPO 的直接前身 |
| [Ternary Feature Masks，CVPR-W 2021](https://arxiv.org/abs/2001.08714) | 每个任务加宽特征，用掩码让旧任务看不见新特征，遗忘为 0 | 用投影代替掩码，定宽，前向与任务无关 |
| [CompoNet，ICML 2024](https://proceedings.mlr.press/v235/malagon24a.html) | 持续 RL：每个任务一个冻结模块，通过动作输出组合旧策略 | 通过隐层特征复用，而不是只传动作 |

**最关键的一条批评：投影本身可能是多余的。**
- 技能编号已知、输出层是线性的。所以只要第 j 个技能的输出层只读它自己那一级（h0 + g1 + … + gj，即前缀和），就同样逐位精确、同样能复用前面的适配器，还不占任何维度。
- 如果前缀和和带投影的版本一样快，投影就只是实现细节。

**能站住的说法**
- 这个构造本身：查不到相同的。
- 抓起→叠方块的结果。
- 闭环发现：存储状态上的偏移不是保持度的代理；遗忘都在抓住之后；学生在自己走到的状态上误差是在老师状态上的 2.2 倍。
- 旧技能的保证不依赖存了哪些状态。

**不能说的**
- 「第一个不遗忘地加技能」：Progressive Nets、Side-Tuning、CompoNet 都做到了。
- 「零空间原理是新的」。
- 「是投影保住了旧技能」：冻结 + 线性输出层就够了。
- 「参数高效」：6–100% 的主干参数，比 LoRA 的 1–2% 重得多。
- FN-PPO 是新算法：它属于 Anthes / OGD / GPM 一族。
- 名字 NSA：和 Native Sparse Attention 撞名。

**必须加的基线**
- 前缀和（决定性）、side-tuning、拼接 / Progressive Net、CompoNet；
- FT-N（复制一份再微调）、每个技能一个 LoRA、PackNet；

**能把它变成贡献的实验**
1. 先做投影消融，规则事先定好：前缀和或拼接的中位 t90 和我们相差不到一个评估间隔，就把投影降为实现细节，论文改叫「定宽 progressive network」。（11-01 10:45 换成按 seed 配对的规则，另加初始化相同的对照 nsa64npr，见文件顶部那节。）

4. 「库效应」：技能越多，新技能只训输出层是否越快。

- **适配器又快又不忘**：
  - 比整网微调快 25%（3 个 seed 都更快），旧技能保持度和原专家一样（原专家 0.992）。
  - 训练结束时，旧输出层在适配后和适配前的表示上的最大差是 8e-7 到 1e-6，浮点误差级别。
  - 0.996 和 0.992 的差别来自训练进程里那个抓起环境多跑过几次 reset，相当于 256 局里差 1 局，不是策略变了。
- **闭环蒸馏也几乎不忘**（0.992–0.996），但学得慢 1.8 倍：在旧技能自己走到的状态上把动作拉回去，代价是速度。系数更小的组和存储状态蒸馏还在 haha-a 的队列里，那边断网，拿不到结果。
- **为什么适配器比整网微调还快（推断）**：
  - 叠方块的大部分过程（接近、抓取、搬运）就是抓起。冻结主干等于把这些能力原样留着。
  - 新技能只需要学「到点松手」，适配器给了它新的容量，又不扰动旧特征。
  - 只训输出层慢（3.1M），是因为没有新容量；整网微调慢一些，是因为它会改动新技能自己也要依赖的抓起特征。
- **必须老实说的局限**：
  - 宽度 256 的适配器有约 14 万个参数，和整个主干差不多。「复制一份网络再整网微调」（FT-N）也能精确保持、1.50M 学会、参数一样多。适配器在同样参数下更快，但参数并不省。
  - 宽度 16 和 64（只占主干参数的 6% 和 25%）02:20 起在跑。
  - 只加一个技能时，它等价于 side-tuning 或 progressive network：冻结主干，加旁路。零空间投影这时多余，旧输出层直接读旧表示也一样。投影要在技能链里才体现价值：所有技能共用一个表示，后面的技能能读到前面技能写进去的特征，每个新技能只写进之前所有输出层都看不见的方向。所以下一步要做技能链（抓起 → 叠方块 → 放置）。

## 11-01 01:40 「同一网络加技能」调研设计工作流的结论（7 个代理，全文在任务输出 wjomh85wy）

**文献：要打的基线比「不保护」强得多**
- [Wolczyk 等，ICML 2024](https://arxiv.org/abs/2402.02868)，「微调 RL 模型其实是遗忘问题」：
  - 只对 actor 做行为克隆（在存下的旧状态上 KL 到旧策略），是保持旧能力最好的办法；只存 100 个状态也有效。
  - 它预测「整网微调 + 小的 KL 项」就能接近整网微调的速度、几乎不忘。我们队列里的蒸馏组就是它。
- [ACCRUE（arXiv 2610.18596）](https://arxiv.org/abs/2610.18596)：Isaac Lab 上接触丰富的插装任务做持续 RL，把旧任务最后几十局缓存下来做蒸馏。遗忘约 5%，曲线下面积和每个任务单独一个模型相当。这是 a2r 插钥匙路线最直接的竞争者。
- [Memory Anchors（arXiv 2608.26545）](https://arxiv.org/abs/2608.26545)，模仿学习：遗忘集中在「旧技能表示最密、动作又冲突」的状态上，和我们 00:50 的闭环诊断（抓住之后）一致。所以「遗忘集中在冲突段」这个观察本身不新。
- [OWL（AAAI 2022）](https://arxiv.org/abs/2106.02940)：每个任务一个输出层 + EWC 保护主干。它的消融说明：只在新任务数据上蒸馏旧输出层（LwF）不够。

**推荐：FN-PPO**
- 做法：
  - 每次迭代，在旧技能的锚点状态上算出「改了就会动旧技能动作」的方向。用逐样本的精确雅可比 Gram 矩阵，不用 Kronecker 近似。
  - 梯度和 Adam 步都投影掉这些方向。
  - 锚点一半来自旧技能在当前网络下自己跑出来的闭环状态，一半来自存下的状态，并按阶段分层（至少一半是抓住之后的）。
  - 不加参数。
- 离线证据：在模仿学习的复现里，它学会「到点松手」和整网微调一样好（冲突段损失 1.60 对 1.82），旧技能偏移小 16 倍（0.21 对 3.36）；同条件下 Kronecker 块投影保护不住（3.16）。
- 新意：算法上是 OGD/GEM/SGP 一类的组合；没找到把输出雅可比的硬投影用在持续或分阶段 RL 上的工作。
- 主要风险是速度：开始时新输出层就是旧输出层的拷贝，新技能 99.6% 的主干梯度落在旧技能的行空间里，可能被投影成「只训输出层」的速度（3.1M）。对策是先只训输出层几次迭代，并给新输出层更大的学习率。
- 判定规则：
  - **成立**：中位 t90 ≤ 1.9M，任何 seed 不超过 2.5M；保持度在 t90 时平均 ≥ 0.98、3M 时 ≥ 0.97，没有 seed 低于 0.95；并且在速度—保持度上胜过闭环 KL。
  - **放弃**：中位 t90 > 2.2M，或保持度平均 < 0.97。放弃后改走备选 OccSplit：按整网微调训练，事后把落在旧技能占用子空间里的那部分更新留成私有。
- **01:40 起用工作流实现**：一人实现、三人分角度审查（数学、和 PPO 的衔接、性能）、逐条核实后修复，只用 CPU 测试。GPU 测试等 haha-a 恢复。

## 11-01 01:15 候选三：零空间适配器，按构造精确保住旧技能（已实现，等 haha-a 恢复后测）

- **想法**：
  - 旧输出层是 8×256 的线性映射，旧技能只「读」最后一层 256 个方向里的 8 个。
  - 最后一层输出在另外 248 个方向上怎么变，旧技能都看不见。对所有状态都成立，包括闭环里走到的新状态。这是你「旧技能只占一小块空间」直觉的精确版。
  - 做法：旧隐层原样冻结，新技能加一个适配器，读输入和旧的第二隐层，把新特征只写进这 248 个方向：h~ = h + (I − P) g，P 是投到旧输出层行空间的投影。两个输出层读同一个 h~。
- **性质**：
  - 旧技能按构造精确保持，不需要存旧状态，也没有近似。
  - 新技能能用全部旧特征，加上适配器写进去的新特征。
  - 以后再加第三个技能，就写进前两个输出层都看不见的方向（256 − 8×2 个）。
- **CPU 验证**（[wrwl/ppo.py](../wrwl/ppo.py) 的 `NullSpaceTrunk`）：
  - 适配器输出很大时，旧输出层的结果也只差 1e-6，是浮点误差级别；
  - 在同一个拟合任务上，损失比只训输出层低一大截（0.033 对 0.087）。
- **一个坑**：适配器不能初始化成零。新输出层一开始是旧输出层的拷贝，同样看不见这 248 个方向，零初始化就永远拿不到梯度。改成随机初始化后，初始策略仍和旧策略完全一样。
- **要测的**：叠方块能不能学得和整网微调一样快。
  - 组名 nsa256，3 个 seed；
  - 训练中每 10 次迭代在抓起上跑一次旧技能（old_eval.csv），作为保持度曲线和精确性的核对。
- **新意要保留余地**：
  - 零空间投影在持续学习里很成熟，但已有工作都是**输入侧、近似**的零空间：
    - [Adam-NSCL（CVPR 2021）](https://openaccess.thecvf.com/content/CVPR2021/papers/Wang_Training_Networks_in_Null_Space_of_Feature_Covariance_for_Continual_CVPR_2021_paper.pdf)：旧任务特征协方差的近似零空间；
    - [AdNS](https://arxiv.org/pdf/2207.12061)；
    - [VPT-NSP（NeurIPS 2024）](https://proceedings.neurips.cc/paper_files/paper/2024/file/0f06be0008bc568c88d76206aa17954f-Paper-Conference.pdf)；
    - [NuSA-CL](https://arxiv.org/html/2510.21175v2)。
  - 最接近的是 [CNSP](https://openreview.net/forum?id=NXduufyPtY)（ICLR 2026 投稿），它把条件拆成「特征保持」和「输出头保持」，但做的是视觉提示，没细读。
  - 思路上和 progressive network（参数隔离）是近亲。
  - 机器人 RL 里加技能的情形，粗搜没找到同样的做法，要正式查新。
  - 卖点要落在：输出侧精确保持、所有技能共用一个表示、后面的技能能复用前面写进去的特征，以及闭环诊断：近似的、基于状态的保护为什么不够。

## 〇点零（续）、23:40 方法的数学草案、复核意见，以及 ρ_B 和真实 D_A 的离线测量

**草案**：对每个隐层，只从新技能的更新里去掉「旧技能占用的输入方向 × 旧技能动作读取的输出方向」那一块，即 ΔW ← G − P_out G P_in。P_in、P_out 分别取 C = E_A[x xᵀ] 和 Q = E_A[Jᵀ J] 的主方向。

**复核意见（你转来的，全部接受）**：
- 这只是「Kronecker 因子化 + 主子空间截断 + 一阶近似」下的近似保证，不是严格的「旧技能不变」；
- 必须报告真实 D_A 和近似 D_A 的差距；
- 必须测 ρ_B，看被挡掉的那一块占新技能更新的多少；
- 偏置用增广的 [x;1]，只投影共享主干，旧头冻结，方差头和值函数单独处理；
- 小步更新，并定期重新估计子空间。

改后的表述：**在 Kronecker 因子化、主子空间截断和一阶近似下，旧技能动作均值的主项不变；尾部方向、层间交叉和非线性残差，通过监控和定期重估来控制。**

## 〇点零二、19:30 第 1 道闸门（初步）：冲突不集中在少数共享单元上

> 两种初始化都跑完了（各 3 个 seed），结论一致。下面的数字以 PickCube 初始化为主，随机初始化单独列在表里。
>
> 20:10 第二轮审查回来，确认了 4 处问题，都出在「冲突集中度」和「稳定性」的读数上：
> - 每个时间点只记一步，冲突在相邻几步间来回摆，所以单步表格上的星号是噪声；
> - 前后两半的重合度会被并列的零值抬高，给出的随机水平也不对。
>
> 验证员同时确认，这些问题都不影响「拆冲突单元 / 随机单元 / 梯度大小相当的单元」三者的比较，结论靠的正是这个比较。下面第 1、2 条已据此改写，脚本的读数部分之后再修。

**数据**：抓起专家 2048 个回合（成功率 97.8%），叠方块专家 2048 个回合（73.2%）。只保留第一次成功之前的状态，按整个回合留出 20% 做测试。测试集里，「抓着停在目标处」的状态抓起有 703 个、叠方块有 684 个，叠方块「在目标附近松手后」的状态有 856 个。网络是一个共享网络同时用行为克隆学两个专家，脚本是 [scripts/conflict_concentration.py](../scripts/conflict_concentration.py)，按两轮审查意见重写过。

1. **冲突不集中（以时间窗平均为准）。** 单步表格是噪声，不作数。按 100 步时间窗平均后：
   - 第 2、3 层，冲突最大的前 1%、5%、10% 单元占的份额都在置换基线的 95 分位以内；
   - 第 1 层平均下来几乎全是同向梯度，冲突只占 0.6–1.6%，集中的是一个可以忽略的量。
2. **冲突单元稳不稳定，目前判断不了（撤回 19:30 的说法）。** 之前报的「第 3 层前后两半重合 0.41–0.71」，算法有两个问题：重合度会被并列的零值抬高，随机水平也算错了。要用更长、互不重叠的窗口重新比较。
3. **拆开冲突单元不比对照好。** 每层拆 12 个单元，给两个任务各一份副本：

   | 拆分方式 | 追回的差距（0 = 只有各自的输出层，1 = 两个独立网络）：PickCube 初始化 | 随机初始化 |
   |---|---|---|
   | 冲突最大的单元 | 0.43 ± 0.01 | 0.31 ± 0.15 |
   | 随机单元（3 个 seed × 5 个随机掩码） | 0.38 ± 0.04 | 0.34 ± 0.19 |
   | 梯度大小相当、但方向一致的单元 | 0.48 ± 0.04 | 0.39 ± 0.06 |
   | 全部共享，连输出层也共享 | −0.48 ± 0.07 | −2.00 ± 0.61 |

   随机初始化时，按时间窗平均后两个任务的梯度几乎都同向：各层的冲突只占梯度总量的 0.2–5%。

   追回的差距主要来自「多出来的参数放在梯度大的单元上」，和这些单元是否冲突无关。

**初步结论**：在「抓起 vs 叠方块」这对任务上，「冲突集中在少数共享单元上，只拆它们就够」不成立。
- 冲突分散在大量单元上。按冲突挑单元来拆，不比按梯度大小挑好，和随机挑也差不多。
- 最大的一步是给每个任务单独的输出层：从全部共享到只分开输出层，就拿到了「全共享 → 两个独立网络」总收益的约三分之一。这正是现在的做法：冻结共享的主干，只训新的输出层。
- 注意：这是行为克隆的代理实验，不是 RL。

## 〇点零五、18:40 为什么「只在冲突区探索比全局学得快」不成立（19:20 按两位质疑者的复核修订）

**由数据直接支持的**
1. **点火不是瓶颈。** 下限 1.0 时，第 1 次迭代就有约 100–156 次成功：全局 96–124 次，人工冲突区 131–156 次，自动冲突区 111–131 次；随机区域少一些，68–87 次。局部的优势有限：

   - 自动冲突区比全局只多 1.04 倍；
   - 训练成功率早约 0.2M 步到 50%。不过训练成功率是在各组自己的噪声下测的，这个差别一部分来自测法。
2. **「到 90%」这个终点把差别压平了。**
   - 评估只有 128 局，0.9 的门槛要求 ≥116 局。真实成功率 0.92 的策略，单次评估有 22% 的概率测不到 0.9；0.90 的则是 52%。
   - 各组曲线在 0.9 附近每个评估间隔只涨约 0.05，所以「第一次 ≥0.9」前后跳一个间隔很常见。
   - 早期其实有差别。叠方块上，1–2M 步时局部的评估平均比全局高 0.08–0.10（各 2 个 seed，不显著）。PlaceCube 上方向相反：1.02M 时全局 0.66–0.88（4 个 seed），局部只有 0.19–0.47（5 个 seed），两组完全分开，置换检验 p≈0.008。
3. **时间大头是整条策略从约 50% 爬到 90%，需要 1.7–2.4M 步，原因还看不出来。**
   - 用均值动作的确定性策略只在 50% 附近明显落后训练策略（落后 0.7–1.4M），到 90% 附近基本追上。
   - 更正：18:40 版本说「时间大头是从靠噪声成功到确定性成功的转换」，这不对。脚本里的「爬坡」对第 1 次迭代就点火的组，按定义就约等于全部时间，所以那个结论是定义带出来的，不是发现。
4. **统计分辨率有限。** 评估每 0.51M 步一次，每次 128 局，跑完的 seed 只有 2–4 个。准确的说法是「到 90% 的时间没看到超过一个评估间隔的差别」。以后的对比要在评估过 0.7 后加密（每 0.1M 一次，≥512 局），同时报固定步数下的评估成功率。

**最可能的漏洞：冲突区只覆盖了一半**
- **机制。** 人工冲突区要求「抓着，且离目标 ≤2.5 cm」（ppo.py 里读的是抓取标志 x[:,18]）。自动冲突区和它几乎重合：探针亮的状态 86% 在人工区内，人工区内 99.6% 探针都亮。下限让夹爪张开、失去接触后，下一步状态就出了冲突区，下限随即关掉，夹爪回到学到的小噪声和偏向夹紧的均值。所以局部下限能触发松手，却维持不了张开。
- **冲突最大的状态在区外。** 12:00 的离线检查里，夹爪冲突最大的两类状态都在冲突区外，只有全局下限覆盖得到：
  - 「松手后、方块在目标附近」：占 30% 的状态，两个专家的开合方向 100% 相反；
  - 「抓着、离目标 2.5–5 cm」：占 12%。
- **间接证据：**
  - 产出检查里人工冲突区 1.0 有 91% 的回合在目标处松手，第一次成功却只有 14.7%；
  - 局部组冲突区外的夹爪噪声在前 1M 步被 PPO 推高，11 个 run 都是这样；
  - 局部组回合结束时方块还在原位的比例更低：叠方块 0.19–0.31 对 0.23–0.60，PlaceCube 0.30–0.44 对 0.54–0.60；
  - PlaceCube 上全局早期明显更快。
- **结论。** 到目前为止比的是「半个冲突区」对「全部状态」，只能说明这种划法下局部不占优，推不出「局部本身没用」。
- **「冲突区以外」那组也不是「冲突区里不探索」的对照：**
  - 它在冲突区里用的是学到的噪声，从 0.27 涨到 0.45–0.66；
  - 下限还覆盖了松手后的状态；
  - 训练后期它只有 1–2% 的状态落在冲突区里。

  它说明的只是「离目标 2.5 cm 这个球不是关键边界」。它到 90% 平均比局部慢约 0.8–1.1M（按 seed 配对是 0–2.0M）。

**下限可能把均值训坏**（假设，在 PushRetreat 和 PlaceCube 上更明显）
- 有下限时，训练成功率很快接近 1，确定性评估却先塌下去。PushRetreat 6 cm 上，评估从源策略的 0.67–0.82 掉到 0–0.02，要停 0.4–0.8M 步才恢复；不加下限的组没有这个坑。
- 可能的原因有两个：
  - std 大时，PPO 的截断允许均值一步走得很远（target_kl 没开）；
  - 评论家从零训练，早期优势估计噪声大，把均值带偏。
- 两种解释都预测：点火后撤掉下限会学得更快，值得直接测。
- 全局下限在冲突区以外的代价也不像 18:40 版本说的那么小。叠方块上，全局的训练成功率到 0.8 要 1.69–1.79M，人工冲突区只要 1.23–1.43M。全局组夹爪噪声的参数在下限之下没有梯度，记录里一直是 0.273。

## 〇、调研结论（13:05）：调研不支持直接开干，按你的条件我没有往下推

你定的条件是「调研符合我们的想法就直接干」。10 个代理（4 路文献、1 路组内情况、3 个设计者、新颖性和可行性 2 个对抗核查）的结论是**不符合**，主要三条：

1. **每一块都有人做过，剩下的空位只有约 3/10 的新颖性。**
   - 「像 PCGrad，但从结构上解决」：Recon（ICLR 2023，按层拆）、Parameter Differentiation（AAAI 2022，带随机对照）、GradPS（ICML 2025，把梯度互相抵消的神经元复制一份）、STGC（ICLR 2025）、CoNAL（AAAI 2023，在 Meta-World 上按冲突长模块）、HarmoDT（2024，RL 里的逐参数任务掩码）。
   - 「按状态局部地拆」：Split-RL（NeurIPS 2026，NVIDIA，用树做局部冲突拆分）；更早有 U-Tree / 变分辨率离散化。
   - 「保留旧策略、只在需要处学新的」：PEX、SPIBB、PARTS（2026，冻结底座、在瓶颈处加残差）、Dodeja 等。
   - 「旧特征表达不了就长新单元」：cascade-correlation、BEBF、TINY、GrowNN。
   - 「在旧预测被推翻处探索」：Pislar 等（ICLR 2022）、MaxQInit；Yardimci & Cogurcu（2026）已经在「熟悉但还不会」的状态加大噪声，且总体没有收益。
   - 我们的备选「Aliased, Not Overloaded」也撞了：Gradient Coupling（2025）就是「相似状态、梯度打架、把表示分开」。
2. **前提在我们要用的地方站不住。**
   - 多任务 PPO 里，冲突主要在评论家网络，不在演员网络（MTBench 2025）；PCGrad 低于普通多任务 PPO，原论文结果复现不出来（Meta-World+ 2025）；多数「解决冲突」的收益其实来自参数量和评论家的规模（McLean 2025、BRC 2025）。
   - VLA 从 SFT 起步做 RL 时，任务间干扰本来就小（RLinf-VLA 一个模型训 130 个 LIBERO 任务到 98%）。
   - 组里的十任务掉点（a2r E-10，`docs/contact-rl-expansion.md`，我核对过原文）：组里把主因定为自适应学习率按各任务 KL 的**最大值**调整，改成平均值后九个任务到 80–100%；剩下的 sweep、egg 是探索和课程问题。所以这不是表示冲突的痛点。
3. **我们在叠方块上测到的瓶颈，组里已经有现成的全局解法。** 叠方块卡在「第一次松手」，组里在放蛋任务上遇到同样的事（PPO 把夹爪 std 压到下限、均值偏向合拢，再也碰不到成功），解法是全局夹爪 std 下限 0.6：第 30–60 次更新成功率 0.56–0.63，第 140 次 0.98。我们的「只在冲突处加探索」要比它强才有意义，核查代理认为最可能的结果是打平。组里还记录了另一个相关现象：从单任务 checkpoint 热启动联合训练，没在 checkpoint 里的任务会「继承一个出不来的模式」（R214、R216），最后正式联合从零训。

所以按你的条件：**我没有开始写新方法，没有停 WRWL 的作业，也没有跑第 1 道闸门。** 已经在跑的 12 个试点作业让它跑完，它回答的正是「在冲突处加探索有没有用」，结果出来我补进第二节。

**线性探针：冻住 PickCube 演员网络的最后一个隐层，只训一个线性输出层，去拟合叠方块专家的动作**（80% 状态训练，20% 留出）：

|---|---|
| PickCube 隐层（复用印象） | **0.937 / 0.920** |
| 同结构、随机初始化的网络 | 0.843 / 0.801 |
| 原始状态（42 维） | 0.810 / 0.771 |

| 阶段 | 不改输出层（手臂 / 夹爪） | Pick 隐层 + 新输出层 | 随机隐层 + 新输出层 |
|---|---|---|---|
| 没抓住，离方块 > 5 cm | 1.30 / 0.07 | 0.47 / 0.29 | 0.94 / 0.87 |
| 没抓住，离方块 ≤ 5 cm | 1.49 / 1.17 | 0.70 / 0.96 | 1.16 / 2.30 |

- **旧印象基本够用**：只换输出层，就能把叠方块要的动作（包括松手）读出来；松手处的夹爪误差从 5.6 降到 0.3 个标准差。比随机特征好一截，未解释的方差少了约 60%。

## 三、subagent 调研（11:52–13:00，10 个代理，全部完成）

**6 个设计和核查结论**（新颖性核查按「新颖性 × 影响」排序，可行性核查按「判决力 / 成本」排序，两者一致把 SEAM 排第一）：

| 设计 | 一句话 | 新颖性风险 | 结论 |
|---|---|---|---|
| SEAM | 冲突前（还没成功时）在源策略「以为做完了、新任务却没给奖励」的地方集中探索 | 高（Yardimci 2026、Pislar 2022） | 保留；和 RTF、正在跑的 frozen_boost 合并；先做 0.1 GPU 小时的探索产出检查，对照组里的全局夹爪下限 0.6 |
| CoFork | 冻结旧印象；某个隐空间格子里的策略梯度持续偏离源策略时，给它一个函数等价的分叉 | 中（c-BTM、SPIBB、Parameter Differentiation、Split-RL） | 保留但只做第一阶段；检测器其实测的是「这里梯度不为零」，很可能退化成按访问顺序逐步解冻 |

| AliasGrow | 旧印象表达不了的更新方向，用 TINY 闭式解长新单元 | 高（cascade-correlation、BEBF、TINY） | 只留离线检查 |

**可行性核查指出的共性问题**（任何后续实验都要照做）：
- 结构改动（开分叉、加噪声）要放在 PPO 更新之后、下一次采样之前，否则采样时的 log-prob 和更新时的策略对不上。
- 噪声和结构要分开测：结构组不加额外噪声。
- 叠方块结果是双峰的，5 个 seed 的「成不成」判据统计功效只有 12–37%；要 8 个 seed、分批加，主指标用训练里的「点着时间」（训练成功率连续 3 次迭代 ≥ 2%）做 Kaplan-Meier 和 log-rank。
- 6 个设计全跑约 21 GPU 小时，预算 6。
