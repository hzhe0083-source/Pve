## 3. 隐空间点云

- UMAP 里各任务基本各占一块。每块里阶段从早到晚排得很整齐，抓住物体的状态在各自任务里自成一片。
- 去掉任务编号以后，任务**仍然**各占一块。所以分块来自场景内容本身（有没有目标、工具、物体尺寸），不是 one-hot 造成的。
- PCA 里能看到跨任务的共享方向：接近阶段的状态在中间重叠；抓着物体的状态（PickCube、LiftPegUpright、StackCube）排成一条带，拿着工具的状态（PokeCube、PullCubeTool）是另一条。
- 关键度在每个任务内部只集中在少数区域。

## 4. D1 预览：不过关

做法是留一个任务出去：用其余 6 个任务训练预测器，在留出任务上打分，7 个任务轮流留出，取平均。目标是 c* 在本任务内的百分位，模型是 ridge 或梯度提升树（各取较好的一个）。

| 用什么预测 | Spearman | 前 10% AUROC |
|---|---|---|
| 隐空间（带 one-hot） | 0.26 | 0.61 |
| 隐空间（无任务编号） | 0.32 | 0.63 |
| 原始观测 | 0.27 | 0.61 |
| 手工特征（距离、抓取、夹爪开合、时间） | 0.18 | 0.56 |
| 只看时间 t/H | 0.20 | 0.63 |
| 用其他任务训练、去预测 p(1−p) 的探针（G2 的正式基线） | 0.19 | 0.62 |
| 参考：用同一批 rollout 算出的真实 p(1−p) | 0.70 | 0.83 |
| 参考：分半上限 | 0.72 | 0.86 |

- **G2 要求**：Spearman ≥ 0.4，AUROC ≥ 0.75，并且比各基线高 ≥ 0.05。现在三条都不满足。
- **问题不在标签噪声**：分半上限有 0.72 和 0.86。
- **跨任务迁移对所有特征都弱**，隐空间也不比原始观测或「只看时间」强。
- **c* 很大一部分是结构性的**：对二值结局有 c* ≤ p(1−p)，关键度只可能出现在结局还没定的状态。真实的 p(1−p) 能做到 AUROC 0.83，但新任务上没有熟练策略，拿不到真实的 p。
- **去掉这个上界之后几乎没有可迁移的信息**：剩下的份额 ρ = c*/p(1−p)，用任何特征做留出预测，Spearman 都只有 0.14–0.23，而分半上限是 0.64。

**少样本版本**（[d1_fewshot.py](../scripts/d1_fewshot.py)）：给留出任务 m 个带标签的状态，在它其余的状态上打分。下表每格是「Spearman / 前 10% AUROC」，取 7 个任务 × 3 次随机抽样的平均。

| 特征 | m | 其他任务 + m 个标签 | 只用这 m 个标签 |
|---|---|---|---|
| 隐空间（无任务编号） | 0 | 0.32 / 0.63 | — |
| 隐空间（无任务编号） | 16 | 0.31 / 0.64 | 0.29 / 0.63 |
| 隐空间（无任务编号） | 64 | 0.40 / 0.68 | 0.42 / 0.71 |
| 原始观测 | 64 | 0.40 / 0.70 | 0.36 / 0.67 |
| 手工特征 | 64 | 0.35 / 0.65 | 0.22 / 0.62 |

- 给 64 个标签也到不了 0.75。
- 「只用这 m 个标签」和「其他任务 + m 个标签」几乎一样，说明其他任务没有帮上忙，跨任务迁移基本为零。
- 隐空间作为任务内部的特征，比原始观测和手工特征略好（只用 64 个标签时 0.71、0.67、0.62）。

**这次预览对 D1 不公平的地方**：
1. 每次只用 6 个任务训练；
2. 隐空间来自行为克隆蒸馏，没有任何压力让不同任务的同类事件对齐；
3. 观测里没有剩余时间；
4. 每个任务只有 256 个状态。

另外，隐空间训练时见过留出任务，这一点只会让结果偏好，不会偏差。所以这是一个提前出现的警告，不是最终判决。

**第 2 周的 D1 要给它公平的机会**：
1. 源任务加到 12 个以上；
2. 用以物体为中心的相对坐标，并加上剩余时间；
3. 隐空间换成为迁移训练的版本，比如多任务成功率预测器或 critic 的特征，而不是行为克隆的 actor 主干；
4. 按正式的 G2 去比「预测的 p(1−p)」。

这样做之后如果还到不了 0.75，就按报告转向：做保底版，或者转 Aliased, Not Overloaded。

## 5. 照抄项单元测试 U2：修好了

测试设置是 θ=0：源策略本身就是目标任务的标准答案。从零初始化，再加一项拉向源策略的 KL，到 80% 成功率应该比从零训练快很多。

| 变体 | 到 80% 的步数 |
|---|---|
| 从零训练 | 0.82M |
| 从零训练，关掉 PPO 早停 | 和上面一样（同一条曲线） |
| 反向 KL，系数 0.5（原实现） | 1.97M |
| 前向 KL，系数 0.5 | 1.23M |
| 反向 KL，系数 0.05 | 0.90M |
| **反向 KL，系数 0.5，关掉 PPO 早停** | **0.08M（快 10 倍）** |
| 前向 KL，系数 0.5，关掉 PPO 早停 | 0.16M（快 5 倍） |

- **原因**：PPO 的 KL 早停是一旦这一轮策略变化超过 0.1 就停止更新。照抄项一开始就把策略往源策略拉，几步就触发早停，所以每一轮只更新了几步。
- **修法**：带 KL 的组关掉早停，照抄项用反向 KL。从零训练关不关早停，曲线完全一样，所以这样对比是公平的。
- M1 已在 00:44 用修好的照抄项重启，剩 71 个实验。E0 已经重新排队：撤掉 PullCubeTool，手工门控改在 LiftPegUpright 和 PlaceSphere 上做。
